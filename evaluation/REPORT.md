# GrassSegHB 256 张初评：ADE20K CNN 与 SegFormer-B0

2026-09-21。**本次不建议用备用 CNN 替换 B0。** ResNet18-dilated + PPM 的可割 IoU 低 15.59 个百分点，模型前向中位数约为 B0 的 1.99 倍。它整体误割率更低，但漏割明显更多。这个结论仅适用于这两个现成 checkpoint、当前预处理与设备，不能据此否定 MobileNet 或所有轻量 CNN。

这里把 ADE20K `grass` 当作可割代理，与 GrassSegHB 人工二分类标注比较；它不是完整的机器人安全评测，也不代表人、动物、小障碍物检测能力。未训练、未接控制系统。

## 数据与可复现性

实际从 [GrassSegHB 官方归档](https://www.informatik.uni-bremen.de/agebv2/pub/grassseghb/) 的 7,491 对图像/标注中按固定种子 `20260921` 选取 256 对。归档 29,431,557,236 bytes，仅通过 Range 下载选定成员，约 971.6 MiB；下载前检查了空间。实际编号 0..15 共 16 组，各 16 张；组内按数值帧号均分 16 段，各段随机选一张。官网地点描述与实际编号组数并不完全相同，不能自行补造地点身份。

[冻结清单](grassseghb-256.json) 保存路径、分组、种子和文件 SHA-256；本次清单 SHA-256 为 `0cf60fb87b4e1290db6a052ef5a37842fb65cecb2bfb786174e0e3ef07aa92cb`。两模型使用完全相同的 256 张原图，每张 4000×3000，每模型共 3,072,000,000 个评测像素。逐图混淆计数与总计已核对。推理代码版本 `4424063d46a6f49e1d544de501f0dcc6451f69a7`，之后提交仅补充报告和结果证据。

全部 256 对通过哈希、尺寸和标签检查，标注只有 0=不可割、1=可割，没有忽略背景。缩略图平均亮度范围 42.64–183.95/255，可割面积比例范围 17.10%–87.76%。每组亮度最低/最高共 32 张已人工查看：包含阴影、逆光、落叶、模糊及过曝，标注与原图大体对齐；草地混落叶及细边缘存在语义/边界不确定性。没有独立复标或标注者一致性测量，不能把这次抽查说成完整标注质量认证。机器检查见 [audit](annotation-audit.json)，人工复查图可由工具重新生成。

这些组已经用于查看表现和失败原因，属于探索性初评。后续训练必须按整庭院或确认独立的采集序列划分；若依据本次结果调参，应另留未参与决策的独立庭院做最终测试，不能逐帧随机划分，也不能将这 256 张继续称作未见测试集。

## 实测结果

以下为原始分辨率的 micro 聚合，非逐图百分比平均；没有用草地面积或置信度代替准确率。

| 指标 | SegFormer-B0 | ResNet18-dilated + PPM |
| --- | ---: | ---: |
| 可割 IoU：TP/(TP+FP+FN) ↑ | 93.52% | 77.93% |
| 不可割误判可割：FP/(FP+TN) ↓ | 5.51% | 3.92% |
| 预测可割中的错误：FP/(TP+FP) ↓ | 2.05% | 1.76% |
| 可割召回率：TP/(TP+FN) ↑ | 95.38% | 79.03% |
| 边界 F1 ↑ | 12.23% | 8.84% |
| GT 边界带错误率 ↓ | 45.58% | 45.87% |

边界采用四邻域标签转变的两侧像素，不算图像外框；在原始 4000×3000 分辨率用半径 3 像素的方形 Chebyshev 容差匹配，再由累计匹配数计算 precision/recall/F1。边界带错误率是 GT 边界同样扩张带内的错误像素比例。这是很严格的原分辨率容差，低分也受低分辨率模型输出和细标注边界影响，不能与不同容差的公开边界榜单直接比较。分母为零记 null，不记满分。

原始统计、每庭院指标及运行配置见 [results-summary.json](results-summary.json)，512 条逐图计数、指标、实际输入尺寸和时间见 [per-image.csv](per-image.csv)。不把同一庭院的相关帧或数十亿相关像素当成独立样本声称统计显著性。

## 速度与尺寸

设备：NVIDIA RTX 5060 Laptop GPU（8151 MiB，驱动 592.27），Intel i9-14900HX，WSL2 Ubuntu 22.04。Torch 2.14.0+cu130 / CUDA 13.0，CPU 线程 4，batch=1，float32；matmul precision=highest、matmul TF32=false、cuDNN TF32=true。每模型预热 5 次，之后各测 256 次，顺序 B0→CNN。未锁定笔记本功耗/温度，不宣称跨设备稳定优势；工具支持反向顺序复测。

| 项目 | B0 | CNN |
| --- | ---: | ---: |
| 原图宽×高 | 4000×3000 | 4000×3000 |
| 实际模型输入高×宽 | 512×512 | 600×800 |
| 参数数（CNN 含辅助头） | 3,752,694 | 24,566,636 |
| 前向均值 / 中位数 / P95，ms | 70.57 / 75.94 / 77.03 | 128.81 / 151.01 / 235.24 |
| 端到端均值 / 中位数 / P95，ms | 2678.74 / 2669.22 / 2859.57 | 2686.70 / 2687.93 / 2881.72 |

前向使用 CUDA Events 并同步，不含传输和输出还原。端到端在边界同步，包含温缓存文件解码、预处理、传输、前向、原尺寸还原和产品可视化；不含权重加载、下载、哈希检查、评测指标、图像保存或 HTTP/浏览器。原分辨率后处理占用较多时间，因此两者端到端接近，不能由此前向时间宣称网页实时速度。本备用 CNN 也并不比 B0 参数更少。

两模型遵循各自官方预处理，均保留整幅图像，无中心裁切；B0 使用 checkpoint 的 512×512 processor，CNN 使用短边 600、长边上限 1000、两边向上取整至 8 的倍数。输出 logits 先还原原图尺寸再 argmax。这是可运行预训练方案之间的比较，不是输入算力、预训练配方完全受控的纯架构实验。

## 同图失败案例

本机完整图集位于 `outputs/grassseghb/index.html`；每个模型目录含全部 256 张原尺寸二值预测和 `<样本名>-comparison.jpg`。对比图依次为原图、标注、预测、错误（红=误割 FP，蓝=漏割 FN），相同样本可并排核查。原图许可不明确，因此图集只保存在忽略目录，不随 PR 再分发；下载和评测工具可重新生成。

| 样本 | 人工检查与量化证据 |
| --- | --- |
| `1G0041734` | B0 将后方树篱部分当草地，FPR 57.41%；CNN FPR 1.07%，但大量漏掉中央真草地，IoU 仅 28.31%（B0 82.15%）。 |
| `15G0031671` | 落叶/裸土小路：B0 把部分路径填成草地，FPR 43.34%、预测可割错误 51.08%；CNN 分别 7.97%、24.17%，但仍漏割邻近草地。 |
| `7G0078062` | CNN 把不少木质长凳/木料当草地，FPR 41.01%、IoU 85.28%；B0 分别 5.46%、97.36%。整体较低 FPR 不能保证逐场景更安全。 |
| `4G0192633` | 落叶与植被混杂地面，两模型均未预测草地：IoU=0、FPR=0，预测可割错误比例无定义。零误割率不能单独表示模型可用。 |

另外对 CNN 两张失败图重新推理，确认二值预测与已保存结果逐像素一致后检查原始 ADE20K 类别。`1G0041734` 的漏割像素主要被分成 tree（约 566 万）和 field（约 43 万）；`4G0192633` 主要为 flower（约 704 万）和 tree（约 81 万）。见 [原始类别诊断](failure-diagnostics.json)。这说明类别/场景迁移存在问题，**不构成把 tree、flower、field 或全部 vegetation 合并为可割的理由**。

## 模型来源、许可和验证

优先候选 MIT MobileNetV2-dilated + PPM_deepsup 的完整权重与配置未能验证：固定官方源码没有该组合配置，按官方目录规则访问两项权重均为 404，目录 403，HTTPS 证书域名不匹配。不能证明其他位置不存在权重。按照预先允许的备用方案，使用官方 ResNet18-dilated + PPM_deepsup 完整 ADE20K encoder/decoder，两项实际下载并严格加载，SHA-256 已固定。官方 MobileNet mIoU 35.76 仅为来源信息，未用于本次结论。

来源、摘要、参数数量和许可记录见 [model-provenance.json](model-provenance.json)，详细说明和命令见 [评测指南](../docs/evaluation.md)。MIT 推理代码 BSD-3-Clause；未找到权重的独立明确许可。GrassSegHB 未找到明确许可证，不能声称商用许可。B0 模型卡指向 NVIDIA 的非商业研究/评估许可。YCOR 官网 CC BY 4.0、RELLIS-3D 官网 CC BY-NC-SA 3.0，本次没有下载它们或 LiDAR。

验证已完成：

- 24 个 Python 测试通过，含非方形全幅保留、输出还原与分块一致性、ADE20K grass 索引、ignore 转换和二分类背景不可忽略。
- 与固定版本 MIT 官方模型及 TestDataset 比较，两张非方形样例预处理完全相同；在 137×211 输出网格上概率最大差异为 0、argmax 完全一致，见 [mit-parity.json](mit-parity.json)。原图尺寸还原另由回归测试覆盖。
- 前端 lint、TypeScript 检查、生产构建通过。
- 真实生产代理对三个模型分别执行三张样例与上传推理，共 12 次请求通过，见 [api-validation.json](api-validation.json)；浏览器实际验证模型切换、上传图跨模型保留、数据集/能力限制提示和完整图片显示。
- 当前 HF 元数据在线冷加载曾导致代理超时；完整缓存后使用 `HF_HUB_OFFLINE=1` 验证通过。未声称首次联网加载在弱网下无风险。

## 是否继续微调

**值得开展有明确停止条件的小规模领域适配实验，但不值得据此立刻大规模训练或替换 B0。** 实测暴露了树篱、木料、落叶及裸土边界的系统性错误，说明仅用 ADE20K grass 代理仍有改进空间；尚无训练结果能证明微调一定有效。

下一阶段应先解决数据与模型使用许可，固定庭院级划分，并以 B0 为现成基准；若目标是轻量部署，另选能验证完整权重且实测参数/算力更小的 CNN，再进行相同标注预算的小规模微调。验收同时约束误割、漏割、边界和目标硬件延迟，按庭院检查失败案例，不能只追求整体 IoU。当前备用 ResNet18+PPM 比 B0 更大、前向更慢，不是轻量替代方案的正面证据；当前二分类评测也不足以支持自动驾驶控制。
